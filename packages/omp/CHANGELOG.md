# @gendigital/sage-omp

## 0.15.0

### Minor Changes

- Add the Oh My Pi connector (`@gendigital/sage-omp`), an in-process hook that guards OMP `tool_call` events. It covers `bash`, `eval`, `debug` (launched programs, evaluate expressions, breakpoint conditions, custom DAP requests), `write`, `read` (local paths and URLs, with schemeless `www.` paths and collapsed `https:/` schemes canonicalized the way OMP's fetcher does), `edit` in every OMP edit mode (`hashline`, `replace`, `patch`, `apply_patch`, `sloppy`), and `ast_edit` (target paths plus replacement templates), so protection holds with hashline enabled or disabled. Edit patches are matched with OMP's own header leniency across all textual grammars, and the raw patch text is always scanned, so a payload whose headers sage cannot parse is still evaluated. Ships as a single CommonJS bundle (`dist/index.cjs`) — the same shape as the pi connector — because sage-core's ESM dist cannot load under Node's ESM loader. Ask verdicts prompt through `ctx.ui.confirm` and confirmed approvals persist for 10 minutes; without a UI (print mode, subagents) ask verdicts block. Core adds `"omp"` to `AgentRuntime`.

### Patch Changes

- Add the pi connector (`@gendigital/sage-pi`), an extension that guards pi `tool_call` events for `bash`, `powershell`, `write`, `edit`, `read`, `grep`, `find`, `ls`, `web_search`, and `url_context`, including tool calls issued from codemode scripts. It ships as a single CommonJS bundle with a `pi.extensions` manifest, so it loads via `pi install` or `pi -e`.
  The pi connector incorporates the pi-specific features of vaclavbelak/pi-sage: tool paths are resolved the way pi resolves them (`@`, `~`, `ctx.cwd`); tool output from `read`, `bash`, and `url_context` is scanned on `tool_result`; approved actions get a note pointing at `~/.sage/exceptions.json`; the status line (`ctx.ui.setStatus("sage", text)`, not a footer) shows blocked/flagged counts and fresh risky-skill findings when `manage_status_line` is on; loaded extensions, packages, and skills are scanned at session start; and the Sage MCP server (`sage_report_false_positive`, `sage_list_audit_entries`) is registered via `pi.registerMcpServer`. pi's runtime version is read from the installed `@earendil-works/pi-coding-agent` package.json (pi exports only `import`, so the package cannot be required).
  The shared handler is **not** in core. `@gendigital/sage-hook-host` exports `registerHookHandlers` (with `HookHostAPI`, `HookUI`, `HookToolMapping`, and `HookHandlerExtensions`): host registration and the verdict-to-hook-result mapping used by the pi and Oh My Pi connectors only. OpenClaw, OpenCode, and Claude Code are unaffected — they keep their own hook shapes and call `guardToolCall` directly. Core only adds `"pi"` and `"omp"` to `AgentRuntime` and the small shared helper those connectors already needed (`formatAskBlockMessage`). The handler forwards `agentRuntime`, `hookType`, and the event `toolCallId` into the audit entry, calls `confirm(title, message)` and `setStatus(key, text)`, sets the idle status line from the `session_start` and `agent_start` handlers, drops the pending approval on a declined, no-UI, or failed prompt, and runs a 5-minute `unref`'d approval sweep (a private helper in hook-host, not a core export) that is intentionally **not** cleared on `session_shutdown` (one handler serves every session). `HookHandlerExtensions` lets a connector add a `tool_result` handler, an approval callback, and its own status rendering. `tool_result` reuses the connector's `mapToolCall`, so an OMP URL `read` stays `WebFetch` and still gets the medium-risk prompt-injection warning. Until the follow-up WebFetch pre-scan lands in core, `url_context` pre-tool PI scanning covers the first URL only; the mapping still sets `url` to that first URL so the audit summary is not empty. OMP multi-file edits are checked for package manifests on the first path only — the core union fix was reverted from this PR and is the same follow-up. `findPiWarningInAuditLog` still matches on tool call id only (ids are unique per session); a session-id filter is also deferred to that core follow-up.
